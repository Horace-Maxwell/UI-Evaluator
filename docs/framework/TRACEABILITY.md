# Traceability

Every adopt item in the [research notes](../research/README.md) has one row here: where it is implemented, or why it was not. `tools/check-traceability.mjs` fails the build when an item has no row, an unknown disposition, an `implemented` or `partial` row that names no criterion, file or section, or a `rejected` or `deferred` row without a reason. Run it with `--write` to add rows for new adopt items; existing dispositions are kept.

| Disposition | Meaning |
|---|---|
| implemented | the practice is a criterion, a workflow or method step, a knowledge rule or a script check; "Where" names them |
| partial | part of the practice is implemented; "Where" names that part and what is missing |
| rejected | not adopted; the reason is given (usually a conflict ruling, a licence limit or a better-evidenced alternative) |
| deferred | worth adopting later; the reason and the condition are given |

The CMU lecture (*Evaluation: Analytical vs Empirical*) is mapped element by element in [FRAMEWORK Appendix A](FRAMEWORK.md#appendix-a--the-cmu-lecture-element-by-element). Conflicts between sources are ruled in the [CONFLICT-REGISTER](CONFLICT-REGISTER.md).

Paths are relative to `skills/ui-evaluator/` unless they name a framework document. Criterion IDs refer to [QUALITY-BAR](QUALITY-BAR.md).
