# Conflict register: rulings on conflicting guidance

| | |
|---|---|
| Version | 2.0.0 (2026-10-04) |
| Status | Normative. Every guidance file follows these rulings. The register is subordinate to FRAMEWORK, QUALITY-BAR and METHODS: where a ruling and a parent disagree, the parent wins and the disagreement is a bug. |
| Parent | [FRAMEWORK](FRAMEWORK.md) |
| Scope | The 111 rows of the "Conflicts and proposed resolutions" tables in research notes 01–07, merged into 69 rulings (`CR-001`…`CR-069`) |

**How to use.** Guidance files (`SKILL.md`, workflows, methods, knowledge files, evaluator prompts, templates and data files) cite the ruling they follow by its ID, for example `[CR-024]`, wherever they touch a topic below, and never restate a different position. A ruling changes only through an ADR in [DECISIONS](DECISIONS.md) that names the CR ID; IDs are never reused or renumbered. Thresholds quoted from [QUALITY-BAR](QUALITY-BAR.md) are copies: if a copy ever differs, QUALITY-BAR wins. When two rulings pull in different directions, the precedence of [FRAMEWORK §3](FRAMEWORK.md#3-principles) applies (P11 accessibility > P12 honesty > P1 context and brief > P9 user evidence > P3 convention > P2/P4 taste). Rulings or parts marked *advisory* guide `direct`, `build` and the critics but never change a gate state. Defects found in the parent documents are listed in §4 and are settled by ADR, not here.

**Reading a row.** *Positions* names sources as the research notes do. *Implemented in* gives QUALITY-BAR criterion IDs (gating unless marked advisory), files under `skills/ui-evaluator/references/` (`knowledge/`, `methods/`, `workflows/`, `evaluators/`), data files under `assets/data/` and `uie` commands. *Origin* gives the note and its conflict row: `02 X15` is note 02 §3.2 row X15, `03 #6` is note 03 §3.2 item 6. Bracketed IDs are research adopt items.
